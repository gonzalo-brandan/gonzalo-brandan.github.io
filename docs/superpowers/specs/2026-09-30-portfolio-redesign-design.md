# Portfolio redesign — design spec

- **Date:** 2026-09-30
- **Branch:** `redesign`
- **Status:** awaiting review

## Goal

Turn gonzalobrandan.com from a Chirpy blog into a portfolio-first site whose look and motion are as close as practical to <https://matthieugivelet.com/>, while keeping all existing content, URLs, the Jekyll build and both deploy pipelines.

The site is a job-search portfolio for entry-level IT, network and data center roles. A recruiter should land on a striking home page, see the two strongest projects immediately, and be able to read any lab write-up comfortably.

## Decisions already made

| Topic | Decision |
|---|---|
| Site role | Portfolio first: Home, Work, Archive, About, Contact. Posts remain full write-ups. |
| Build approach | Custom Jekyll theme inside this repo, plain CSS and JavaScript, no JS libraries. Chirpy is removed. |
| Featured work | "Creating a redundant network" and "From Fundamentals to Enterprise Complexity". |
| Features kept | Table of contents on posts, giscus comments, site search, tag pages, light/dark mode, syntax-coloured code blocks. |
| Features dropped | Chirpy sidebar, categories pages, RSS icon, PWA/offline mode, code copy button. |
| Reference boundary | Look and motion are recreated with new code. No CSS, JS, text, images or font files are copied from the reference site. |
| Font | Inter Tight (OFL, free), self-hosted as woff2. The reference's GT Standard is commercial and not used. |

## Visual language

- Background white (`#FFFFFF`), text black (`#000000`), borders black at 10% opacity, one accent yellow (`#FFFB24`) used sparingly (text selection, small highlights, hover marks).
- Dark mode inverts: background near-black, text white, same accent.
- Very large type sized in `vw` with `clamp()` limits so phones stay readable.
- Small uppercase-free labels in square brackets: `[ Berlin ]`, `[ Approach ]`, `[ Work ]`.
- Thin 1px horizontal rules that draw in from left to right.
- Easing curves defined once as tokens (a soft ease-out for reveals, a stronger in-out for page transitions).

## Pages

| Page | URL | Content |
|---|---|---|
| Home | `/` | Animated headline "I like solving infrastructure problems", `[ Berlin ]` label, short "Approach" statement, the two featured projects as large image cards, link to About. |
| Work | `/work/` | The featured projects as full-width cards: image, title, tags, year, summary. |
| Archive | `/archives/` (same URL as today) | Every post as a Name / Topic / Date list separated by thin rules. Hovering a row shows the post's image beside the cursor (pointer devices only). |
| Post | `/posts/:title/` (unchanged) | Big title, date, tags, table of contents beside the body on wide screens (collapsible above it on phones), body text, coloured code blocks, giscus comments, "Next post" link. |
| About | `/about/` (unchanged) | Intro line in large type, photo that scales from 1.3 to 1.0 as the page scrolls, "How I got here" text, "What I build" as a numbered 01/02/03 block. Wording stays as currently published. |
| Tags | `/tags/` and `/tags/:name/` (unchanged) | Index of all tags with counts; one page per tag listing its posts in the Archive row style. |
| Search | `/search/` | Text input that filters all posts by title, tags and body text as you type. |
| 404 | `/404.html` | Large "Not found" message in the same style, link home. |

URLs that go away: `/categories/` and `/categories/:name/`. `/feed.xml` keeps working (generated by `jekyll-feed`) but is not linked in the UI. These are not linked from the CV or LinkedIn.

## Site-wide elements

- **Top bar:** name on the left; Work (2), Archive (6), About, Contact and a light/dark switch on the right. Counts come from the data, not hard-coded.
- **Menu:** on narrow screens the links collapse into a "Menu" button that opens a full-screen overlay with large links and a Search link; "Close" dismisses it. Escape also closes it and focus is trapped while open.
- **Skip link:** a "Skip to content" link is the first focusable element on every page.
- **Footer:** `[ Open ]` invitation text, email and LinkedIn links, `©` year and name.

## Motion

| Animation | Behaviour |
|---|---|
| Loader | A 0–100% counter and a panel that lifts away. Shown once per browser session (sessionStorage); skipped if storage is unavailable. |
| Text reveal | Lines of headings and labels slide up from a clipped mask with a small stagger when they scroll into view (IntersectionObserver). Each element animates once. |
| Rules | Horizontal rules scale from 0 to full width when they enter the viewport. |
| Images | Project images fade and scale in slightly when they enter the viewport. |
| Page transitions | Clicking an internal link fades the current page out, then navigates normally; the next page fades in on load. Modified clicks (new tab), external links, anchors and downloads are left alone. The back/forward cache is handled so a restored page is never stuck faded out. |
| Archive cursor image | On pointer devices, hovering a row shows that post's image following the cursor with a slight lag (requestAnimationFrame). |
| About photo | Scales from 1.3 to 1.0 as the page scrolls. |

All motion is disabled under `prefers-reduced-motion: reduce`: content appears immediately, the loader is skipped, transitions are instant.

Without JavaScript every page still shows all content (reveal starting states are only applied when a `js` class is on `<html>`); search is the only feature that needs JavaScript and says so.

## Architecture

### Dependencies

`Gemfile`: replace `jekyll-theme-chirpy` with `jekyll` (~> 4.3), `jekyll-seo-tag`, `jekyll-sitemap`, `jekyll-feed`, `jekyll-archives` (for `/tags/:name/`). Keep `html-proofer` in the test group.

`_config.yml`: remove Chirpy-only settings (theme, PWA, CDN, analytics, pageviews, theme_mode, avatar handling that depends on Chirpy, `jekyll-archives` categories). Keep title, tagline, description, url, social, giscus settings, kramdown/rouge settings, the posts default permalink `/posts/:title/`, and the `exclude` list. Disable categories in `jekyll-archives`.

### Files

```
_layouts/   default.html  home.html  work.html  archive.html  post.html  page.html  tag.html
_includes/  head.html  header.html  menu.html  footer.html  loader.html
            toc.html  comments.html  project-card.html  archive-row.html
_sass/      _tokens.scss  _base.scss  _layout.scss  _animations.scss
            _components.scss  _post.scss  _syntax.scss
assets/css/ main.scss
assets/js/  main.js  loader.js  reveal.js  transitions.js  menu.js
            cursor-image.js  photo-scale.js  theme.js  search.js  toc.js
assets/fonts/  inter-tight (woff2, latin subset, regular + medium)
work.md  archives.md  about.md  tags.md  search.md  404.html  search.json
```

`_tabs/` is removed; its About content moves to `about.md` with the same permalink. `_sass/abstracts` and `assets/css/jekyll-theme-chirpy.scss` from Chirpy are removed.

Each JS module exports one `init` function, does one job, and uses no libraries. `main.js` adds the `js` class, applies the saved theme, and calls only the modules whose elements exist on the page. `theme.js` has a tiny inline part in `<head>` so the saved theme is applied before first paint.

### Content model

- `featured: true` and `summary:` front matter on the two featured posts drive Home and Work.
- The existing `image:` front matter drives project cards and the Archive hover preview.
- The Archive "Topic" column uses the post's category.
- `search.json` is generated by Liquid at build time: title, url, date, tags, and body text with HTML stripped.

## Error handling and edge cases

- Posts without `image:` get a plain text card and no hover preview.
- The loader and theme code wrap every storage access in try/catch.
- Search with no matches shows "No posts match".
- The table of contents is omitted on posts with fewer than two headings.
- Very long titles wrap; large type never causes horizontal scroll at 320px width.

## Testing

- `htmlproofer` (already run in both deploy workflows) must pass on the built site: no broken internal links or images.
- A URL check script compares the list of post, about, archives and tag URLs from the current live sitemap with the new build; every one must exist.
- Browser checks at 375px and 1440px widths, light and dark, and with reduced motion, for Home, Work, Archive, a long post, About, Tags, Search and 404.
- Keyboard check: menu open/close/focus, skip link, visible focus styles.

## Rollout

1. All work happens on the `redesign` branch; the live site is untouched.
2. The user reviews the site on localhost and approves.
3. Merge to `main`; the existing workflows build, test and deploy to AWS and GitHub Pages.
